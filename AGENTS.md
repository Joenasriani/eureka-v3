# Eureka repository instructions

## Source hierarchy

The files in `source/` govern reasoning behavior. Do not replace their epistemic rules with a single model prompt.

The product target is an experience anchored Eureka candidate that changes the representation of admitted events and exposes a move, question, prediction, or test that was not naturally available under the prior account.

Bisociation is important but is not the complete definition of Eureka. Preserve selective G1 to G18 routing.

## Non negotiable separations

Evidence status, structural status, personal fit, user recognition, and transfer outcome are independent. No code path may promote one because another improved.

User recognition belongs to the user. The system may estimate candidate quality but cannot set `CLICKS` or `STRONG_AHA` itself.

A real world transfer result is scoped to the observed case. It does not certify the entire source model.

## Personal material

Preserve exact user supplied anchors. Do not invent history, traits, motives, diagnoses, or abilities.

Stored cases may enter P1 retrieval only under explicit permission.

Imported Person Context is personalization material, not external evidence. Preserve item provenance when present. Candidate inferences remain separate and stay disabled for retrieval unless the user explicitly permits them. Direct biography notes do not automatically become P1 episodes. Prior structured Eureka cases outrank broad imported history when both contain comparable personal source material.

## Retrieval

Structure comes before source selection. Familiarity affects bridge cost, not structural truth. Semantic similarity may propose a source but cannot verify the mapping.

A failed candidate should be repaired at the earliest faulty stage. Do not solve a bad source selection by polishing final copy.

## Public language and surface

Read `docs/PRODUCT_LANGUAGE_RULES.md` before changing public text or CSS.

Do not add en dash or em dash characters to the public surface.

Do not introduce generic chat UI, floating rounded panels, decorative gradients, glass effects, glow decoration, ornamental neural graphics, or copy that could be pasted into unrelated AI software.

Use the reasoning architecture itself as the interface grammar.

## Tests

Run `npm test` after changing parser, retrieval, leveler, verification, feedback, storage, server routes, public copy, or public styling.

Do not weaken a failing regression test to make a build pass unless the source contract itself has changed and the change is documented.
