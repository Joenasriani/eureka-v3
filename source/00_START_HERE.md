# Eureka Reasoning Architecture v5.5-proposed - Experience-AHA / Right-Bisociation Modular AI Kit

## Purpose

This revision preserves the canonical Eureka architecture's evidence-first, structure-first, routed, adversarial, and fail-closed design while making **personal representational unlocks** a first-class routed outcome for `UNLOCK`, `ACT`, `LEARN`, `CREATE`, `INFLUENCE`, and `REFLECT` intents.

The target is not generic personalization, not a large list of perspectives, and not an interesting analogy. The target is:

> From the user's own story, experience, language, attempts, successes, failures, tensions, and goals, identify what the current representation cannot explain or enable; search for a structurally legitimate second matrix or other re-representation; return that shift to concrete moments in the user's own experience; and expose a new prediction, question, option, wording, behavior, or reversible test that was not naturally visible before.

The architecture must never guarantee an AHA. It may generate `RIGHT_BISOCIATION_CANDIDATE` or other `EUREKA_CANDIDATE` objects and estimate representational gain. Only the user can report whether a candidate actually clicked.

## Orthogonal status axes - never collapse these into a ladder

```text
1. EVIDENCE STATUS
   How well external factual/causal propositions are supported.

2. STRUCTURAL STATUS
   Whether the source-target mapping or re-representation is legitimate.

3. EXPERIENCE-FIDELITY / PERSONAL-FIT STATUS
   Whether the reframe is traceably anchored to the user's actual input.

4. USER-RECOGNITION STATUS
   Whether the user reports NO_CLICK / INTERESTING / CLICKS / STRONG_AHA / KNOWN_ALREADY / DOES_NOT_FIT.

5. TRANSFER-OUTCOME STATUS
   What happened when the user applied or tested the resulting move in context.
```

No axis promotes another. A click is not truth. Strong evidence is not proof of personal AHA. A successful micro-transfer does not automatically validate the source analogy or a universal causal mechanism.

## Core invariant

```text
GENERATION MAY PROPOSE.
USER EXPERIENCE MAY ANCHOR.
STRUCTURAL MAPPING MUST JUSTIFY TRANSFER.
EVIDENCE MUST SUPPORT EXTERNAL FACTUAL CLAIMS.
USER RECOGNITION MAY CONFIRM A PERSONAL AHA EXPERIENCE ONLY.
REALITY MAY SUPPORT OR WEAKEN A TRANSFER IN CONTEXT.
PERSONAL RESONANCE MUST NEVER INFLATE EVIDENCE STRENGTH.
FINAL WRITING MAY NOT CREATE NEW FACTS, NEW EUREKAS, OR NEW PERSONAL HISTORY.
```

## Recommended execution order for a personal unlock

```text
USER STORY / INPUT
-> 02 ORCHESTRATOR + INTENT / UNLOCK ROUTER
-> 03 EPISTEMIC LEDGER + EXPERIENCE GRAPH
-> AHA TARGET: TENSION, OPPORTUNITY, OR TRANSFER GAP
-> TARGET RELATIONAL SIGNATURE
-> PERSONAL + REMOTE + CONTRASTIVE SOURCE POOLS
-> 04 RIGHT-BISOCIATION / RE-REPRESENTATION SEARCH
-> EXPERIENCE BRIDGE + STORY REPLAY
-> 05 CLAIM + EXPERIENCE ATOMIZATION
-> 06 EVIDENCE RETRIEVAL / SOURCE AUDIT WHEN NEEDED
-> 07 CLAIM VERIFICATION
-> 08 STRUCTURAL + EXPERIENCE-FIDELITY + REFRAME-GAIN VERIFICATION
-> 09 ADVERSARIAL + COUNTER-ANCHOR REVIEW
-> 10 FIVE-AXIS ARBITRATION
-> 11 DEPTH + CROSS-EPISODE + SELF-TRANSFER TEST
-> 12 MICRO-TRANSFER / ACTION / DECISION
-> 13 FINAL RED TEAM
-> 14 AHA-FIRST RESPONSE COMPILER
-> USER RECOGNITION RESPONSE
-> NO_CLICK / KNOWN_ALREADY / DOES_NOT_FIT: RE-ROUTE IF USEFUL
-> CLICKS: APPLY OR TEST WHEN APPROPRIATE
-> REAL-WORLD OUTCOME
-> LEARNING
```

## Primary acceptance test for a personal AHA candidate

A strong personalized candidate should, when the input permits:

1. trace to actual user material;
2. identify a concrete unresolved tension, latent opportunity, or transfer gap;
3. introduce a genuinely distinct representation or second matrix;
4. share meaningful relations with the target rather than surface resemblance;
5. make at least one concrete story detail mean something materially different;
6. preferably clarify multiple independent details or episodes without ad hoc additions;
7. produce a different prediction, question, option, wording, behavior, or reversible test;
8. survive a counter-anchor and competing-frame attack;
9. state important boundaries and defeaters;
10. avoid claiming novelty or AHA until the user reports it;
11. when possible, enable the user to restate or transfer the new frame to another episode without the AI.

## Compatibility with the canonical PDF architecture

The v5.1 PDF's governing architecture remains the baseline: discovery must survive evidence; bisociation remains **one generator rather than the universal definition of Eureka**; structure precedes deliberate distant-domain retrieval; AHA intensity is not evidence confidence; high-AHA candidates receive stronger scrutiny; null outcomes remain valid; and reality/evidence outranks additional speculation.

This v5.5 proposal is therefore a **routed personal-AHA extension**, not a replacement of the general architecture.
