# App Pipeline Implementation Notes - v5.5 proposed

## Product target

For personal use the app should feel like:

> **Tell me what happened, what you tried, what worked elsewhere, or what you want to change. I will search for the second model or re-representation that makes your own experience look different, test the connection, and help you transfer it into the next real moment.**

The default result is an experience-anchored Eureka candidate, not a report of internal lenses.

## Pipeline zones

```text
ZONE 0: USER EXPERIENCE INTAKE
Raw story / situation / goal
Epistemic ledger + Experience graph
Tension / opportunity / transfer gap

ZONE 1A: STRUCTURE EXTRACTION
AHA target
Target relational signature
Old-frame blind spot / unused strength

ZONE 1B: SOURCE RETRIEVAL
P1 intra-personal episodes
P2 familiar user worlds
P3 remote external worlds
P4 contrastive cases

ZONE 1C: COLLISION / RE-REPRESENTATION
Explicit relational mapping
Experience bridge
Story reinterpretation
Old-frame/new-frame prediction or move delta

ZONE 2: VERIFICATION
Claim + Experience Atomizer
Evidence retrieval when required
Claim Verifier
Structural Verifier
Experience-Fidelity + Reframe-Gain Verifier
Adversarial + Counter-Anchor Review

ZONE 3: FIVE LEDGERS
Evidence ledger
Structural ledger
Personal-fit ledger
Recognition ledger
Transfer-outcome ledger
No cross-promotion

ZONE 4: USER RECOGNITION
AHA Card
CLICKS / INTERESTING / KNOWN ALREADY / DOESN'T FIT
No-click may reroute source search

ZONE 5: DEPTH + SELF-TRANSFER
Story replay
Cross-episode check
Counter-anchor
Optional user restatement / self-transfer

ZONE 6: MICRO-TRANSFER / ACTION / DECISION
Small next move

ZONE 7: OUTPUT + REALITY
Final Red Team
AHA-First Compiler
No new claims
Real-world outcome when available

ZONE 8: LEARNING
Recognition feedback
Transfer outcome
Evidence/outcome update
Retrieval/routing update without truth promotion by repetition
```

## Experience graph is first-class

Do not reduce a user's history to a flat profile embedding. Preserve episodes and only input-supported relations such as same pattern/different outcome, prior success/current failure, repeated friction, expectation violation, role-to-role transfer, feedback delay, bottleneck, or information pattern.

## Retrieval indexes

```text
STRUCTURE INDEX
relational signatures across cases/domains

EXPERIENCE GRAPH INDEX
user-authorized episodes, relations, attempts, successes/failures

PERSONAL SOURCE PALETTE
user-authorized domains, roles, crafts, metaphors

EUREKA PATTERN LIBRARY
prior candidate structures/mappings; never evidence by repetition

CONTRASTIVE CASE INDEX
similar structures with different outcomes/boundaries
```

Retrieve broadly enough to avoid both familiar-source and exotic-source bias. Rank only after structural mapping.

## AHA card

```text
YOUR MOMENT
THE GAP
THE SECOND MATRIX
THE COLLISION
THE AHA CANDIDATE
LOOK BACK AT YOUR STORY
WHAT BECOMES VISIBLE
TRY / NOTICE THIS NEXT
WHERE IT BREAKS
```

For low-stakes use, detailed epistemic status can be expandable. For consequential cases, evidence, boundaries, and uncertainty must be prominent.

## Recognition loop

```text
CLICKS -> record recognition; apply/test if useful
INTERESTING -> sharpen or compare
KNOWN ALREADY -> search a more novel/different matrix if useful
DOESN'T FIT -> inspect experience bridge and reroute; never argue
```

Optional follow-up:

```text
What part clicked?
What do you see differently now?
Where else in your own experience does this relation show up?
What would you try differently next?
```

These improve personalization/transfer and do not validate external truth.

## Practical modes

```text
PRODUCTIVITY: start, focus, prioritize, finish, sustain, recover, coordinate
INFLUENCE: clarify, persuade ethically, create relevance, negotiate, teach, lead, mobilize
CREATION: generate, select, reframe, differentiate, communicate, iterate
LEARNING: understand, remember, transfer, practice, discriminate
DECISION: choose, preserve options, reduce uncertainty, test, commit
```

## Influence integrity

Influence outputs must preserve meaningful autonomy and reject coercion, exploitative targeting, or deception that materially removes informed choice.

## Implementation invariant

Every factual statement shown to a user must trace to an inspected source, user-provided fact, deterministic calculation, formal derivation, or explicit inference/assumption. Every personalized statement must also trace to admitted experience anchors/episodes or explicit recognition feedback.

The final renderer/compiler accepts only approved structured objects. It does not invent new facts, analogies, source matrices, causal claims, or personal history.
