# Eureka build plan

## Stage 1: Local working system

Status: built.

The current app runs without third party packages. It includes experience intake, traceable anchors, an experience graph, AHA target classification, relational signature extraction, P1 through P4 retrieval, an adaptive bisociation Leveler, local source matrices, candidate generation, claim atomization, structural and personal fit checks, counter anchor review, five independent status axes, recognition feedback, rerouting, micro transfer outcomes, persistent local case history, and retrieval learning.

## Stage 2: Open source matrix discovery

Status: wired, requires model credentials for live use.

When `OPENAI_API_KEY` is present, Eureka can ask one model pass to propose unfamiliar P2 and P3 source matrices. A separate review pass must accept at least two target relations before the source can enter the candidate set. A later pass can improve candidate wording while the local anchor and structure checks remain active.

## Stage 3: Evidence service

Status: not yet built.

Add live evidence retrieval and source auditing for external factual claims. Keep this separate from structural correspondence. Consequential cases must remain closed until evidence standards appropriate to the domain are satisfied.

## Stage 4: Production storage and identity

Status: not yet built.

Replace the local JSON state file with a relational database. Add user accounts, access control, episode authorization, deletion controls, and encryption appropriate to autobiographical data. Keep vector search as a secondary retrieval index rather than the canonical store.

## Stage 5: Broader generator execution

Status: partial.

The registry includes G1 through G18 and the router selects relevant generators. The current local candidate construction is strongest for G2, G3, and G5 with support from contradiction, information, bottleneck, optionality, and related relations. Add generator specific execution contracts and tests for every family without forcing all generators on every case.

## Stage 6: Evaluation corpus

Status: started.

Current tests cover productivity, influence, transfer, false parser matches, fake familiarity, weak relation transfer, five axis integrity, null outcomes, rerouting, Leveler feedback, and HTTP persistence. Add a larger set of real anonymized stories with human recognition labels and delayed transfer outcomes.

## Definition of complete production system

A real user can submit a story, inspect and correct what Eureka admitted, authorize episodes for future use, receive structurally tested candidate representations at an appropriate conceptual distance, inspect evidence where factual claims matter, report recognition, test a bounded transfer, return with the outcome, and receive better future retrieval without recognition or repetition being promoted into truth.
